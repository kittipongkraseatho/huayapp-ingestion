# รหัส VIP แบบ CRUD — Design Spec

## เป้าหมาย

เปลี่ยนระบบรหัส VIP จากการรองรับรหัสเดียวเป็นรายการรหัสที่เพิ่มได้ไม่จำกัด โดยแต่ละรายการกำหนดวันหมดอายุแยกกันได้ ส่วนสูตรคำนวณและข้อมูลสูตรเดิมไม่เปลี่ยนแปลง

## ขอบเขต

- เพิ่มรหัส VIP
- แก้ไขรหัส VIP
- ลบรหัส VIP
- กำหนดวันหมดอายุรายรหัส หรือเว้นว่างเพื่อไม่จำกัดอายุ
- ปลดล็อกด้วยรหัสใดก็ได้ที่มีอยู่และยังไม่หมดอายุ
- ป้องกันรหัสซ้ำโดยไม่สนใจตัวพิมพ์เล็ก/ใหญ่
- รองรับทั้ง LocalStorage และ Firebase ผ่าน Store เดิม
- ย้ายค่าเดิม `vipCode` เข้า list อัตโนมัติเมื่อพบข้อมูลเก่า
- ไม่เปลี่ยนฟิลด์หรือพฤติกรรมของสูตรคำนวณ

## โครงสร้างข้อมูล

เพิ่มฟิลด์ใน config:

```js
vipCodes: [
  { id: 'stable-id', code: 'VIPDRJR', expiry: '' },
  { id: 'stable-id-2', code: 'VIP2026', expiry: '2026-12-31' },
]
```

`id` ใช้ระบุรายการตอนแก้ไข/ลบ, `code` เป็นรหัสที่ผู้ใช้กรอก และ `expiry` เป็นวันที่รูปแบบ `YYYY-MM-DD` หรือ string ว่าง

ข้อมูลเก่าแบบ `vipCode` ยังคงอ่านได้ชั่วคราวและถูก normalize เป็น `vipCodes` ตอนโหลด config เพื่อ backward compatibility; การบันทึกครั้งถัดไปจะเขียน `vipCodes` เป็นหลัก

## การตรวจสอบรหัส

- trim ช่องว่างหัวท้าย และแปลงเป็นตัวพิมพ์ใหญ่ก่อนเก็บ/เปรียบเทียบ
- ห้ามรหัสว่าง
- ห้ามรหัสซ้ำแบบ case-insensitive
- วันหมดอายุที่มีค่าต้องเป็นวันที่ถูกต้อง
- รหัสที่หมดอายุเมื่อเทียบกับวันปัจจุบันหลังเวลา 23:59:59 ของวันนั้น ให้ปฏิเสธการเข้าใช้
- ถ้ารหัสไม่ตรง ให้แสดงข้อความรหัสไม่ถูกต้อง
- ถ้ารหัสตรงแต่หมดอายุ ให้แสดงข้อความรหัสหมดอายุพร้อมวันที่

## UI หลังบ้าน

ใน tab `รหัส VIP & สูตร` เพิ่มส่วนจัดการรหัส VIP เหนือส่วนสูตรเดิม:

- ฟอร์มรหัส VIP + วันหมดอายุ + ปุ่มเพิ่ม/บันทึก
- รายการรหัสทั้งหมดพร้อมสถานะวันหมดอายุ
- ปุ่มแก้ไขเติมข้อมูลกลับเข้าฟอร์ม
- ปุ่มลบพร้อม confirm
- ยกเลิกโหมดแก้ไขได้

ปุ่มบันทึกการตั้งค่าหลักยังคงบันทึกสูตรคำนวณและค่าตั้งค่าอื่นตามเดิม แต่ไม่ใช้ช่อง `admin-vip-code` เป็นแหล่งข้อมูลหลักอีกต่อไป

## ความเข้ากันได้และความเสี่ยง

- รหัสเดิม `VIPDRJR` ต้องใช้งานได้ทันทีหลัง deploy แม้ผู้ใช้ยังไม่มี `vipCodes`
- ถ้า config ไม่มีทั้ง `vipCodes` และ `vipCode` ให้ใช้ค่าเริ่มต้น `VIPDRJR`
- ไม่ลบรหัสเก่าออกจาก config ในทันที เพื่อให้ระบบเก่าหรือ cache เดิมยังอ่านได้
- สูตรคำนวณยังอ่าน `formulas` เดิมและไม่ถูกแก้ไขโดย CRUD รหัส VIP

## การทดสอบยอมรับงาน

- เพิ่มรหัสไม่หมดอายุแล้วล็อกอินผ่าน
- เพิ่มรหัสมีวันหมดอายุในอนาคตแล้วล็อกอินผ่าน
- รหัสหมดอายุแล้วล็อกอินไม่ผ่านพร้อมข้อความถูกต้อง
- เพิ่มรหัสซ้ำแล้วไม่สร้างรายการเพิ่ม
- แก้ไขรหัสและวันหมดอายุแล้วค่าที่บันทึกเปลี่ยนจริง
- ลบรหัสแล้วล็อกอินด้วยรหัสดังกล่าวไม่ผ่าน
- ข้อมูลเก่าแบบ `vipCode` ถูก migrate เป็นรายการโดยอัตโนมัติ
- สูตรคำนวณและค่าฟิลด์ `formulas` ไม่เปลี่ยน
